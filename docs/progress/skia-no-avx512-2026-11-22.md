# Skia without its AVX-512 raster path, 22 November 2026

Div now compiles Skia with `-USK_ENABLE_AVX512_OPTS`, so it has the same CPU
raster paths as Chromium.

**User-facing effect:** before this change, Div on a CPU with AVX-512 could
render differently from Chromium. Upstream Skia selects a raster path for
those CPUs that Chromium does not build.

## Cause

- Skia's `BUILD.gn:126` (rust-skia a31b86b) always defines
  `SK_ENABLE_AVX512_OPTS`, and `src/core/SkOpts.cpp:59-60` then selects the
  SKX path at run time on an AVX-512 CPU.
- Chromium 147.0.7727.50's `skia/BUILD.gn` builds only `skia_opts_hsw` for x86
  (lines 833 and 868) and never mentions the macro.
- On the SKX path, `rcp_fast` is `_mm512_rcp14_ps`. On the AVX2 path it is
  `_mm256_rcp_ps`. The two estimates differ, so blend modes built on
  `rcp_fast` can round differently.

Only this macro is removed. In the pinned Skia it appears only in `BUILD.gn`
and `SkOpts.cpp`, so skcms keeps its AVX-512 path, as Chromium's does.
`SKCMS_DISABLE_SKX` is not set.

## The change

- `-USK_ENABLE_AVX512_OPTS` joins all 10 Skia flag lists. Skia's compile rules
  place `{{defines}}` before `{{cflags}}` on MSVC-style and GCC-style
  toolchains (`gn/toolchain/BUILD.gn:122,135,255,264`), so the `-U` wins.
- `tools/ci/check_skia_flags.py` runs in CI and fails if a Skia flag list
  omits the `-U` or defines the macro.

## Verification

Run [45113924542](https://github.com/build-with-div/div/actions/runs/45113924542)
and run [45123063142](https://github.com/build-with-div/div/actions/runs/45123063142)
used one temporary branch carrying this flag and the gradient PR
([#126](https://github.com/build-with-div/div/pull/126)). That branch is
deleted. Scope: the 31 `gradient-composite` canvases, compared byte for byte.

| OS | CPU | AVX-512 | Div against same-machine Chromium |
| --- | --- | --- | --- |
| Linux | Intel Xeon 6975P-C | yes | 0 pixels differ |
| Linux | AMD EPYC 7763 | no | 0 pixels differ |
| Windows | AMD EPYC 9V45 | yes | 0 pixels differ |
| Windows | AMD EPYC 7763 | no | 0 pixels differ |

- **Windows on Intel was not compared.** That attempt, on a Xeon 8573C, crashed
  in capture cleanup when Chrome still held a file in its temporary profile.
- In the built objects, `SkOpts` references `Init_hsw` and not `Init_skx` on
  Linux and on Windows with this flag. The unflagged census base build
  references `Init_skx`.
- `python3 tools/ci/check_skia_flags.py` reports 10 lists, and
  `python3 -m unittest tools.ci.test_check_skia_flags` passes 6 tests.

with each commit's own CI Skia flags and one shared Chromium cache:

**0 of 23,728 Div images changed**, and all 23,728 Chromium images are
identical between the two runs. The head's first run stopped on an
out-of-memory error while hashing the binary, before rendering anything. The
result above is its rerun on the same binary, whose hash matched the build
receipt. The pair was measured on `main` `3b6ec37d`, before this branch was
rebased. CSS Grid coverage was not run.

The census machine (Intel i9-12900KF) has no AVX-512, so **the census cannot
show this change's effect on AVX-512 machines**. It shows only that a machine
without AVX-512 renders the same.

## A separate variation, not fixed here

On AMD CPUs, pinned Chromium itself renders 7 pixels of the
`gradient-composite` oracle differently from Intel. Div matches same-machine
Chromium there. This flag does not change that, and it is handled in #126.
